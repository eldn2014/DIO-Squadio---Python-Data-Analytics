Comandos simples git e windows

    Controle de versões

  • Git Clone url: Clona um repositorio que esta na nuvem para a sua máquina
  • Git Clone url xpto: Clona um repositorio que esta na nuvem para a sua máquina dentro que uma pasta chamada xpto especificada no final do comando
  • Git Clone url --branch xxx --single-branch: Clona um repositorio que esta na nuvem para a sua máquina, clando apenas a branch especifica.
  • Git Commit: Grava as alterações que você fez no repositorio clonado na sua máquina
  • Git Pull: Puxa para o repositorio que esta na sua máquina, uma versão atualizada do repositorio que esta na nuvem e atualiza o seu repositorio
  • Git Push: Envia para o repositorio na nuvem o commit que você fez.
  • Git remote -v: Mostra se o diretorio é local ou remoto.
  • Git remote add origin xx(url)xx:Vincula seu diretorio local ao remoto.
  • Git status:Mostra os Staatus do commits que ainda não foram efetuados os pushs.
  • echo exemplo/ > .gitignore: A pasta ou arquivo mencionado antes do sinal de maior que será ignorado pelo commit.
  • echo > .gitignore: Se tiver algo no arquivo git ignore, depois desse comando ele ficara vazio.
  • .gitkeep: Esse não se trata de um comanco mas sim de um arquivo onde o git reconhece um diretorio vazio para os seus commits, pois caso contrario o diretorio vazio será ignorado pelo commit do git.
  • git log: Mostras os commits efetuados
  • git init: quando setado dentro do uma pasta esse comando inicializa um repositorio com a pasta em questão
  • rm -rf .git:Remove o init que foi dado em uma pasta errada.
  • git restore xpto.txt:O comando git restore restaura um arquivo para a sua ultima versão que foi commitada e enviada.
  • git commit --amend -m"xxxxx":Muda a mensagem do ultimo commit.
  • git reset --soft 123456abc: Apaga um commit epsecificado no comando.
  • git reflog:Mostra todos as modificações relaizadas no seu repositorio.
  • git add . :Adicona tudo para ser commitado.
  • git remote add upstream xxx(url)xxx :Quando fazemos um ofrk de um repositorio e queremos deixar esse repositorio sempre atualizado com as modificações que foram feitas no repositorio origem.
  • git pull upstream main:Faz a mesma coisa que o pull do repositorio, so que dessa vez é o pull do repositorio origem do fork


    • Configurações

  • git config --global user.name "xxxxx": Aqui setamos o username do git que iremos usar mesmo username do github
  • git config --global user.email xxxxx: Aqui igual ao username tem que ser o mesmo email que usamos no github
  • git config user.name: Aqui verificamos o user que esta configurado no global
  • git config user.email: Aqui verificamos o email que esta configurado no global
  • git config --global --list: Mostra todas as configurações setadas no seu git
  • git config --global credential.helper store: No proximo clone que você realizar de um repositorio, o git salvara a sua credencial login e senha
  • git config --global credential.helper cache:No proximo clone que você realizar de um repositorio, o git salvara temporariamente a sua credencial login e senha
  • git config --global credential.helper Mostra qual o tipo de aramazenamento esta sendo usado (cache ou store)
    • Em casos onde o codigo acima mostre como store e você queira mudar pra cache basta usar o codigo do cache(git config --global credential.helper cache)
  • git config --global --show-origin credential.helper: Este comando mostra o caminho da máquina onde esta salvo o arquivo de senha utilizado pelo git.
  • cat .gitconfig: Basicamente mostra as configurações do seu git como username, email, helper(credential)
  • cat .git-credentials Pega o arquivo se senha e login do helper e mostra o login e senha( no caso token )

Autenticando chave via SSH

  Para verificar se ha alguma chave SSH cadastrada no seu git digite no gitbash o seguinte codigo.

ls -al ~/.ssh

 Esse codigo verifica se há chaves existentes.
 Agora vamos gerar uma nova chave.

ssh-keygen -t ed25519 -C "xxx email github xxx"

  Quando você apertar enter ele vai pedir um local de salvamento, porem se vc apertar enter novamente ele vai salvar no local padrão.

  Apos isso ele irá pedir uma passphrase, esse passphrase serve como uma senha, só que em vez de palavras é uma frase.

  Apos isso vamos adicionar na nossa chave privada ssh ao nosso agent para torna-lá mais segura

eval "$(ssh-agent -s)"

ssh-add ~/.ssh/id_ed25519

  Quando rodar os dois comandos acima de forma independentes 1 do outro, ele irá pedir a passphrase. Agora o proximo passo é adiconar a chave publica ao github para isso vá no github no seu repositorio e clique no seguinte caminho:

foto do perfil>Settings>SSH and GPG keys>New SSH keys.

  Quando você clicar nesse caminho ele vai pedir alguns dados;
   Titulo: Serve pra identificar a sua chave ssh
   tipo da chave: autentication key
   chave: Chave publica gerada no passo anterior

  Para pegar essa chave digite os seguintes comandos:

cd ~/.ssh
ls
cat id_ed25519.pub

  Após isso se ocorrer tudo certo irá mostrar a chave publica abaixo do comando.
